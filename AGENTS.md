# Afterwork

Десктопный трекер продуктивности для Windows 10/11 x64. React + TypeScript работают в WebView2, Rust/Tauri отвечают за таймер, JSON-хранилище, трей и работу с играми.

Инструкции по установке инструментов, запуску и выпуску: [DEVELOPMENT.md](DEVELOPMENT.md). Пользовательское поведение описано в [README.md](README.md).

## Как работать в репозитории

- Перед правкой посмотри `git status --short` и прочитай код затронутого сценария. Сохраняй уже внесённые изменения и держи правку в рамках задачи.
- Если задачу можно решить несколькими способами, опирайся на существующие решения проекта. Уточняй намерение, когда от выбора зависит поведение приложения или сохранность данных. В остальных случаях действуй самостоятельно.
- Для ручной проверки по умолчанию используй превью или Afterwork Dev. Если проверка требует изменения основного профиля или блокировки реальной игры, согласуй это с пользователем.
- В итоговом сообщении опиши результат, выполненные проверки и причины пропуска применимых проверок.

## Версии и сборка

- Для каждого обновления приложения повышай версию. Указывай одну и ту же версию в `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` и `src-tauri/tauri.conf.json`.
- После каждого крупного изменения (например, новой функции или существенной переработки интерфейса, логики или хранения данных) запускай из корня проекта `npm run tauri -- build`. Убедись, что создан NSIS-установщик новой версии, и приложи в итоговом сообщении ссылку на готовый файл `*_x64-setup.exe`.

## Как проверять изменения

Из корня проекта: `npm ci` устанавливает зависимости из lock-файла, `npm run check` проверяет типы TypeScript, собирает фронтенд, проверяет Rust через rustfmt и Clippy и запускает тесты. Запускай `npm run check` при изменении кода.

| Что изменилось | Дополнительная проверка |
| --- | --- |
| Интерфейс | Прогони затронутый сценарий в `npm run dev:preview` (http://localhost:1422) или Afterwork Dev. Превью имитирует команды Tauri и хранит изменения в памяти до перезагрузки страницы. |
| Окно Tauri, трей, системные диалоги | Используй `npm run dev:desktop`. Afterwork Dev хранит данные отдельно от установленного приложения. Обычный `npm run tauri -- dev` использует основной профиль. |
| Блокировка игр | Запусти `cargo test --locked --manifest-path src-tauri/Cargo.toml enrollment_blocks_new_launches_and_exclusion_keeps_history`. Тест сам создаёт временную копию `ping.exe`. В Afterwork Dev блокировка отключена. |
| IPC | Сверь обработчик и типы в Rust с клиентом в `src/desktop.ts`, типами в `src/types.ts` и имитацией в `src/preview.ts`. При изменении контракта обнови соответствующие примеры в `fixtures/`. |
| Формат JSON | На синтетических данных и во временном каталоге проверь чтение старого формата, сохранение и повторное открытие. Начни с `fixtures/legacy-afterwork.json`. |
| Установщик или выпуск | Запусти `npm run tauri -- build` для проверки сборки NSIS. Порядок проверки версий и подписи описан в `DEVELOPMENT.md`. |

## Карта проекта

- `src/main.tsx` — оболочка, таймер, настройки. `activities.tsx`, `statistics.tsx`, `games.tsx` и `achievements.tsx` — соответствующие экраны.
- `src/desktop.ts` — клиент Tauri, `src/preview.ts` — реализация для браузера, `src/types.ts` — типы IPC.
- В `src-tauri/src/`: `main.rs` — интеграция с Tauri, IPC, атомарное сохранение и блокировка файлов; `actions.rs` меняет состояние, `model.rs` считает время и статистику, `achievements.rs` начисляет награды.
- Там же `game_catalog.rs` и `game_detector.rs` распознают игры, `game_tracking.rs` ведёт историю, `game_icons/` работает с иконками.

## Правила поведения приложения

- Активный таймер учитывает сон и перезапуск приложения; пауза останавливает учёт. Статистика делит сессии по настраиваемой границе дня, а достижения используют фиксированную границу в 06:00 по местному времени.
- Архивирование занятия и исключение игры сохраняют прошлые сессии. Уже запущенная игра продолжает работу при включении блокировки.
