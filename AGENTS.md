# Afterwork

Десктопный трекер продуктивности для Windows 10/11 x64: React и TypeScript в WebView2, Rust и Tauri для состояния, хранения, трея и интеграции с Windows. [DEVELOPMENT.md](DEVELOPMENT.md) описывает настройку, профили и выпуск, [README.md](README.md) — поведение для пользователя.

## Перед изменением

- Из корня выполни `git status --short`, проверь незакоммиченные изменения и прочитай код и ближайшие тесты затронутого сценария. Для навигации используй `rg --files` и `rg -n`; исходники приложения в `src/` и `src-tauri/src/`. `node_modules/`, `dist/`, `target/` и `src-tauri/gen/` генерируются инструментами.
- Сохраняй изменения пользователя. Следуй существующим решениям; не совмещай локальную правку с перестройкой модулей или обновлением зависимостей. Уточняй намерение, когда выбор влияет на пользовательское поведение или сохранность данных.
- Node и Rust закреплены в `.node-version` и `rust-toolchain.toml`. Используй Windows x64 с MSVC для нативных проверок. Если зависимостей фронтенда нет или изменился lock-файл, выполни `npm ci`. Для PowerShell, который блокирует `npm.ps1`, используй `npm.cmd` с теми же аргументами.

## Как найти нужный код

Начинай с точки входа сценария и переходи по вызовам. В таблице пути Rust указаны относительно `src-tauri/src/`.

| Сценарий | Точки входа и связанный код |
| --- | --- |
| Окно, настройки, навигация, таймер | `src/main.tsx`; действия таймера в `actions.rs`, расчёт времени и расписания в `model.rs` |
| Занятия, цели, статистика, награды | `src/activities.tsx`, `src/statistics.tsx`, `src/achievements.tsx`; мутации в `actions.rs`, агрегаты в `model.rs`, правила наград в `achievements.rs` |
| Игры | `src/games.tsx`; правила распознавания в `game_catalog.rs` и `game_detector.rs`, история в `game_tracking.rs`, блокировка в `Engine::sync_locks`, иконки в `game_icons/` |
| IPC и хранение | `src/desktop.ts` → `generate_handler!` в `main.rs` → соответствующая команда. `make_snapshot` собирает ответ, `Engine::load` и `Engine::update` читают и атомарно сохраняют `Data` из `model.rs` |
| Трей, автозапуск, фоновые задачи | `main.rs`: `main`, `worker`, `autostart`; настройки окна и разрешения в `src-tauri/tauri*.conf.json` и `src-tauri/capabilities/` |
| Обновления и выпуск | `src/updates.tsx` и `UpdateStatus` в `src/desktop.ts`; `updates.rs`, `src-tauri/tauri.conf.json`, `.github/workflows/release.yml` |
| Превью и инварианты контракта | `src/preview.ts` имитирует IPC; `fixtures/` содержит общие примеры IPC и старый файл данных. Ищи Rust-тесты по `#[cfg(test)]` рядом с реализацией |

## Инварианты при изменении кода

- Бизнес-правила desktop-режима живут в Rust; TypeScript отображает ответ и отправляет действия через `desktop`. При изменении IPC сверь аргументы, имена полей, варианты перечислений и различия между отсутствующим полем и `null`: Rust с Serde, `src/types.ts` или `src/desktop.ts`, `src/preview.ts` и соответствующий пример `fixtures/ipc-*.json`. Имена полей не везде используют один регистр.
- Хранимые метки времени — Unix-секунды; `Date` в JS принимает миллисекунды. Таймер учитывает сон и перезапуск, пауза останавливает учёт. Статистика использует настраиваемую границу местного дня, достижения — фиксированную границу 06:00. В тестах расчётов передавай время явно и проверяй обе стороны границы.
- Архивирование занятия и исключение игры сохраняют историю. Уже запущенная игра продолжает работу при включении блокировки. При изменении `Data` сохраняй чтение старых файлов; проверяй загрузку, сохранение и повторное чтение на копии `fixtures/legacy-afterwork.json` во временном каталоге.

## Проверка и выпуск

- Для короткого цикла используй `npm run check:frontend` (типы, примеры IPC и сборка фронтенда) или `npm run check:rust` (rustfmt, Clippy, тесты). Один Rust-тест: `cargo test --locked --manifest-path src-tauri/Cargo.toml <имя_теста>`. Перед завершением изменения кода запускай `npm run check` — это и команда Windows CI. Если среда мешает выполнить часть проверок, выполни доступные и укажи конкретную причину пропуска.

| Что изменилось | Дополнительная проверка |
| --- | --- |
| Интерфейс | `npm run dev:preview`, http://localhost:1422; выбери `?scenario=…` из [списка сценариев](DEVELOPMENT.md#браузерное-превью). Данные в памяти сбрасываются при перезагрузке. |
| Окно Tauri, трей, системные диалоги | `npm run dev:desktop` (Afterwork Dev, отдельный профиль и порт 1421). Заверши через трей. |
| Блокировка игр | Тест `enrollment_blocks_new_launches_and_exclusion_keeps_history` сам создаёт временную копию `ping.exe`. В Afterwork Dev блокировка отключена. |
| Установщик, выпуск или крупное изменение приложения | `npm run tauri -- build` из корня. Проверь наличие NSIS-установщика новой версии в `src-tauri/target/release/bundle/nsis/` и приложи ссылку на конкретный `*_x64-setup.exe`. |

- Основной профиль (%APPDATA%\app.afterwork.desktop), обычный `npm run tauri -- dev` и реальные игры используй для проверок только по согласованию. Не устанавливай собранный пакет поверх основной версии для проверки сборки.
- Для каждого обновления приложения повышай версию синхронно в `package.json`, обоих корневых полях версии `package-lock.json`, `src-tauri/Cargo.toml`, записи пакета `afterwork` в `src-tauri/Cargo.lock` и `src-tauri/tauri.conf.json`. Проверь `npm run check:versions`. Изменения только в документации и инструментах разработки не требуют новой версии приложения.
- Каждый релиз собирай и подписывай локально на Windows x64, затем публикуй вручную в GitHub Releases как Latest. Перед отправкой тега исключи его из триггера `.github/workflows/release.yml` в коммите выпуска. Отправляй тег и публикуй выпуск только по запросу пользователя. Для локальных проверочных сборок ключи подписи не нужны.
- Для ручного подписанного выпуска сначала проверь `%USERPROFILE%\.tauri\afterwork.key`, `afterwork.key.pub` и `afterwork.password.dpapi` в том же каталоге. Под текущим пользователем Windows прочитай DPAPI-файл через `ConvertTo-SecureString` и передай пароль через `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` только на время подписи. Удали пароль из окружения или восстанови прежнее значение в `finally`. Если файл отсутствует или не расшифровывается, попроси пользователя ввести пароль локально. Держи пароль и приватный ключ вне чата, логов и репозитория.
- Собери установщик с действующим открытым ключом обновлятора. Если подписываешь установщик отдельной командой, передай `tauri signer sign --app-version <версия>`. Проверь подпись перед публикацией и загрузи установщик, `.sig` и `latest.json`. После публикации проверь, что публичный `releases/latest/download/latest.json` отдаёт новую версию и её подпись.
- В конце проверь `git diff --check` и `git status --short`. Сообщи результат, выполненные проверки и причины пропуска применимых проверок.
